# ゲーム仕様

更新日: 2026-10-15 / 状態: 共通のゲーム仕様を試作へ採用し、4ステージを実装

追記: 同日のオーナー確認により、以下の推奨案を試作へ採用した。操作・数値・今回の範囲は [prototype.md](prototype.md) を参照。

## 確定事項

### 目的と基本ループ

プレイヤーは穴を操作し、空間にあるオブジェクトを飲み込む。
飲み込んだ総量によって穴が段階的に成長し、より大きな物を狙えるようになる。
ステージ固有の目標物を飲み込むとクリアする。制限時間と失敗条件は設けない。

1. 現在の穴に入る物を探す。
2. 穴を移動させ、物を落とす。
3. 飲み込んだ量を蓄積し、次の段階へ成長する。
4. 家や巨大な建造物を飲み込める大きさになり、目標物を狙う。

### 対応環境と操作・表示

- ブラウザで動作し、PCとスマートフォンを対象とする。最終的にiPhoneも想定する。
- スマートフォンでは指ドラッグで操作する。
- PCではドラッグに加えてWASD・矢印キーでも移動できる。斜め移動の速度は単独方向と同じで、キーを離す・フォーカスを失うと停止する。
- ゲーム画面内では文字選択・長押しメニュー・ブラウザの要素ドラッグを抑え、指ドラッグがブラウザの選択操作へ切り替わらないようにする。
- 穴の中心は画面中央に固定され、移動時には周囲の空間が動いて見える。
- 穴の画面上の大きさも一定。成長するとカメラが遠くなり、周囲の物が小さく見える。
- ゲーム内の実際の穴は拡大する。表示の縮小だけで成長を代用しない。

### 落下

- オブジェクトには物理演算を適用する。
- 穴の上では物が落下し、穴の縁で傾いたり滑ったりする挙動を目指す。
- 飲み込めるかどうかは、大きさ・形状・姿勢と穴の関係に左右される。
- 接触しただけで即座に消す処理は、物理的な落下の代わりにはしない。

### ステージ

- ステージ制とし、目標物、地形、オブジェクトの種類はステージごとに固有とする。
- 配置はランダムでよい。
- ステージに合った配置ポリシーで生成する。街では道路沿いに配置し、個々の初期配置データを管理しない。
- 同じ物を縦に積む配置も扱う。広場には20段の小箱、山には20段の薪束と6段の井桁積みの丸太、アメリカには20段のハンバーガーの紙箱と6段のタイヤを置く。段数・個数は試作用の仮値。
- 広場の面積を初期版の1.5倍にする。56×56から約68.6×68.6へ広げる。
- ステージごとに1種類の動くオブジェクトを配置する。広場・アメリカ・エジプトは人、山はたぬき。
- 広場に山・アメリカ・エジプトを追加し、選択して遊べる。目標は順に記念塔・森の大樹・自由の女神・ピラミッド。固有の物と配置は [stages.md](stages.md) を参照。
- 山は平らな森と山の背景。アメリカの人の銃撃は光・弾の見た目・音だけで、ダメージや物への影響はない。
- クリア表示を約3秒見せてから、広場・山・アメリカ・エジプトの順で自動的に次へ進み、エジプトの次は広場へ戻る。開始時・プレイ中のステージ選択も使える。

### 目標物の置き直し

- 目標物をタップすると、現在の水平位置で直立させる。速度・角速度もリセットする。
- 目標物以外へのタップには反応しない。ドラッグをタップと誤判定しない。
- 置き直しで成長量・回収数・クリア状態を変更しない。回収済みの目標物は復活させない。
- 重なりを避けるため、置き直す場所に他の物がある場合は、その上方から配置する。

### 成長

- 成長は8段階。飲み込み時にポイントを加算する基準を維持する。
- 成長時には光の輪・粒子・レベル表示・上昇する効果音を組み合わせ、成長の達成感を表現する。
- 成長基準は個数・体積のどちらでもよく、開始から終盤まで同じ基準を使えるものを検討する。
- 各段階の穴半径・必要量は試作用の仮値を `prototype.md` に記録する。

### 動くオブジェクト

- 普段はランダムに選んだ方向へ直線的に歩く。穴に気づくと走って反対方向へ逃げる。
- 穴にも物理的に落下し、他の物と同じ回収・成長ルールを適用する。
- 試作では穴の縁からの距離で気づいたか判定する。人数、速度、距離、方向変更間隔は仮値として記録する。
- 落下が始まったら歩行制御を解除し、傾きと落下を物理演算へ任せる。

### 効果音

- 飲み込み・成長・クリアに効果音を付ける。BGMは今回の範囲に含めない。
- 広場とエジプトの人が穴へ落ち始めた瞬間に、悲壮感のないコミカルな「あーーーー」を約1.6秒鳴らす。アメリカの人は「あー」の代わりに「Damn it!」と言う。人の声は後半ほど音量を下げ、遠ざかる落下を表現する。
- たぬきには約0.5秒のかわいい「きゅーっ」を鳴らす。声はどの種類も落下開始に1回だけ再生し、音のON/OFFに従う。
- 操作を契機に音を有効にし、音のON/OFFを切り替えられるようにする。
- 音の初期化に失敗してもゲームを継続でき、失敗を表示して再試行できるようにする。

## 提案: 成長ポイント

各オブジェクトに、概算体積を基にした正の `growthValue` を事前定義する。
飲み込み完了時に一度だけ加算し、累積値が成長段階の閾値に達すると次へ進む。

```text
飲み込み完了 → 累積ポイント += オブジェクトの growthValue
累積ポイント >= 次段階の累積閾値 → 成長段階を進める
穴半径 = 成長段階に対応する半径
```

- 小物から建造物まで同じ加算規則を使う。途中で個数方式から体積方式に切り替えない。
- 形状の寸法から概算値を作り、遊びやすさに応じてデータ上で調整する。
- 見た目のメッシュ体積を毎フレーム計算しない。物理上の質量と成長ポイントは分ける。
- 一度に複数の閾値を超えた場合は到達段階まで進め、最大段階を超えない。
- 穴半径と必要ポイントは別の表で定義する。具体的な数値は試作で検証する。

個数方式も加算の負荷は同程度に小さい。体積を基にする提案の理由は、大きな物を飲み込む価値を表現しやすいこと。
実際の物理負荷は、同時に演算する物の数や衝突形状を測定して管理する。

## 提案: 試作の体験

- 斜め上から見る3D空間。カメラの向きと画角は固定する。
- 平らな地形の仮ステージ1つ、小物・中型・大型の物、仮の巨大目標物を用意する。
- 建物を含め、まずは各オブジェクトを壊れない1つの剛体として扱う。
- 穴の段階、次の成長までの進捗、目標物、クリア表示を最小UIとする。
- 初期配置は重なりを避けたシード付きランダムとし、同じ配置を再現できるようにする。
- 各段階で次へ成長できるだけの到達可能な物を配置し、生成による進行不能を避ける。
- 自動吸引や落下を強制する補助力は初期案に含めない。必要なら物理検証後に相談する。

### 飲み込み完了とクリアの判定案

物全体が地表より十分下の回収面を通過した時点で、飲み込み完了とする。
物の中心だけで判定して、上部が残っている建造物を消さない。
完了した物は描画・物理世界から除去し、二重加算を防ぐ。
目標物も同じ完了判定を使い、完了イベントでステージをクリアする。
回収面の深さと、穴が移動している途中の落下物の扱いは物理試作で検証する。

## 試作前にオーナーと確定すること

| 論点       | 推奨案                                                           | 決める理由                                           |
| ---------- | ---------------------------------------------------------------- | ---------------------------------------------------- |
| 表現・破壊 | 斜め上からの3D、まずは壊れない剛体                               | 衝突形状とアセットの範囲を決める                     |
| 操作の意味 | 指の移動量に応じて穴を移動、指を離すと停止。PCは左ボタンドラッグ | ドラッグ量方式と押し続ける操縦方式では操作感が異なる |
| 成長基準   | 事前定義した概算体積ポイント                                     | 数値設計の共通基準を決める                           |
| 最初の範囲 | 仮の平坦な1ステージで操作からクリアまで                          | 本物の都市制作より先に核の体験を評価する             |

操作速度、成長段階・閾値、カメラ角度、物の数、摩擦・回収深さなどの試作用数値は、実装前に仮値と明記して提示する。
縦横画面の対応範囲、対応するiPhone・ブラウザの最低条件、地形境界は試作仕様と併せて扱う。クリア後は確定事項の約3秒後の自動切り替えを採用する。

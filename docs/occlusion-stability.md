# iPhone試遊後：半透過のちらつき対策

2026-11-06 / ローカル版。オーナーから「iPhoneではおおむね動くが、一部重く、PCよりちらつきが多い。手前の物の半透過が要因に見える」と報告があった。iPhone上の原因を直接計測した結果ではない。

2026-11-07追記: オーナーがiPhoneで他の場所の改善を確認した一方、最初の箱で移動中だけ残る細かな揺れを報告。[カメラと物理更新の周期差の対策](box-motion-stability.md)を追加した。以下は前日の半透過の修正と検証の記録。

## 確認できた原因と修正

従来は、透過する物を構成するメッシュをすべて通常の半透明へ切り替え、深度の書き込みを止めていた。この方式では、重なった部品の描画順が視点移動で変わり、実際の面の前後と一致しない色の切り替わりが起こる。

実際の `HoleOcclusion` を使う検証場面で、交差する赤・青の部品を微小な視点移動の前後で描いた。800×600と390×844・DPR2の両方で、部品内部の80×80ピクセルの観測領域全体に色の切り替わりを再現した。修正後は同じ領域の変化が0になった。これはPC Chromium・MSAA 4サンプルの特定の再現場面の測定であり、iPhone全場面でちらつきがなくなったという結果ではない。

- 描画先でMSAAが有効な場合は **alpha-to-coverage** を使う。サブピクセルの一部へ描画することで透過を表現し、透過中も深度を保つ。部品同士を半透明の描画順で重ねることを避ける。時間や乱数で点模様を入れ替える方式は使わない。
- MSAAが使えない場合は従来の半透明描画へ戻す。観測用スナップショットの `occlusionRendering` に実際のサンプル数と `coverage` / `blend` を記録する。この変更のためにMSAAのサンプル数や端末の解像度を増やさない。MSAAがない環境では、部品の透明描画ソート自体は従来方式のままで、濃さの固定と材質再利用が適用される。
- 透過時の濃さを物ごとに25%へ固定した。従来は透過対象の数で全対象の濃さが変わっていたため、別の物の出入りによる明滅を防ぐ。MSAAでは表示濃度がサンプル数に応じた段階になる。
- 透過用の材質は、元の物が存在する間は再利用する。透過から戻るたびの材質の破棄と、再進入時の複製・シェーダー準備を避ける。回収・撤去・ステージ終了時には破棄する。フレームレート向上を実機で実測したものではない。

## 維持した条件

透過を始めるのは、現在の姿勢では穴へ入らない大物が、穴の中心と周囲8点のすべてを実際に遮る場合だけ。小物・一部だけを隠す物・机の脚の間のような空間は対象にしない。短い判定欠落の猶予は従来の0.12秒、補間時間も従来どおり。飲み込める大きさになった場合は即座に元の材質へ戻す。

共有材質、物理演算、回収・成長・クリア、オブジェクトの寸法・配置・動作は変更しない。設定ファイル・依存関係・配信設定の変更はない。

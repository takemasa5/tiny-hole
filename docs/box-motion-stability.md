# 最初の箱で残る、移動中の細かな揺れ

2026-11-07 / ローカル修正。前日の半透過修正後、オーナーがiPhoneで「他の場所は改善したが、最初の箱の壁が微小に動くように見える。移動中だけで、止めると収まる」と確認した。

同日その後、オーナーが修正版で「レベル1では激しく点滅、レベル2では治る」と確認した。[箱全体の不要な透過への追加修正](container-occlusion-fix.md)を実施。以下は前の表示補間とPCでのタイミング確認の記録で、iPhoneの点滅が解消したという記録ではない。

## 調査と修正

最初の箱はこの段階では固定剛体で、壁・閉じた側面・蓋の位置を穴に追随させていない。箱を物理的に揺らす処理もない。一方、穴の移動と物理演算は1/60秒刻みで進み、従来のカメラはその離散的な位置を各描画フレームでそのまま追っていた。描画周期と物理周期が一致しない場合、静止した壁まで「止まる→跳ぶ」を繰り返して見える。

この段付きを実ゲームの最初の箱で再現し、表示だけを前後の物理状態の間で補間するようにした。

- カメラ、見えている穴・縁・底、床の穴抜き、遮蔽判定は同じ表示用の穴位置を使う。穴は引き続き画面中央で、画面上の大きさも一定。
- 物理床は実際の穴位置で従来どおり更新する。無地の地面メッシュの位置だけを表示用の差分へ合わせ、描画のために物理床を作り直したり移動したりしない。
- 動的なオブジェクトと落下する囲いも位置・回転を同じ時間割合で補間する。表示補間で剛体の位置・速度・回転を書き換えない。
- 成長による穴の位置補正は、その時点で表示の履歴も合わせる。古い位置から大きな穴を横滑りさせない。
- 最初の箱など固定中の壁は、カメラと一緒に動かさず、元の世界座標を維持する。

当たり判定、物理更新頻度、支持を失ったときの傾き・落下、成長段階、開放条件、回収・クリアは変更しない。表示は最新の物理状態から最大1物理刻み（約16.7ms）以内の遅れを持つ。前日の半透過の描画方式・濃さ・対象条件も維持する。

## 検証方法と根拠

`checks/box-motion.mjs` は実ゲームをシード42で開始し、390×844・DPR2でキー入力によりレベル1の箱内を移動する。検証時だけ描画コールバックをタイマーで60回/秒・120回/秒相当にし、ゲームへ渡した時刻、物理位置、表示位置、穴の画面内位置、箱の位置と姿勢を記録する。実機のディスプレイ更新率やiPhoneのFPSを計測したものではない。

修正前の120Hz相当では、観測した移動中の24区間に7回、物理更新待ちのために表示位置が止まった。修正後は同様の24区間で、物理位置は8回据え置かれていても、表示位置の据え置きは0回だった。60Hz相当でも速度の段付きを改善した。上下移動でも同様に再確認し、120Hz相当の24区間で修正前8回・修正後0回だった（[上下の修正前](../reports/box-stability-2026-11-07/before-vertical/results.json) / [上下の修正後](../reports/box-stability-2026-11-07/after-vertical/results.json)）。入力・タイマーの実行回数は環境で変わるため、この値を全端末の性能保証には使わない。

修正後の検証では、移動中も最初の箱の位置・姿勢は不変、停止後の表示位置の変動は0、穴の画面中央からのずれは浮動小数の誤差範囲だった。表示と物理位置の差も1物理刻みの最大移動量以内に収まった。

# 秘密情報・個人情報の検査

更新日: 2026-10-16

gitleaksをローカルのコミット前とpush前に実行する。標準のAPIキー・トークン・秘密鍵のルールを維持し、メールアドレス、ユーザー名を含むホームディレクトリの絶対パス、連絡先ラベル付きの電話番号を補助ルールで検出する。検出時や検査エラー時は操作を中止し、ログの検出内容は全体をマスクする。コメントによる検査除外は受け付けない。

## セットアップ

Macでは以下を一度実行する。新しくcloneした環境でも必要。npm依存は増やさない。

```sh
brew install gitleaks
npm run hooks:install
```

導入時のバージョンは8.30.1。フックはこのリポジトリだけの `core.hooksPath` を `.githooks` に設定する。既存の別フック設定がある場合は上書きせず停止する。gitleaksやNode.jsが使えない環境でも、検査を省略してコミット・pushを通さない。

## 手動確認と対象

```sh
npm run secrets:check
npm run secrets:history
node checks/secrets.mjs
```

- コミット前・`secrets:check`: ステージ済みの変更。新規ファイルは `git add` 後に検査する。
- push前・`secrets:history`: 全ローカル参照のコミット履歴。履歴がなければその旨を表示する。削除済みでも過去のコミットに秘密情報が残っていれば検出する。
- `.env*` と `DO_NOT_READ/` はGitの除外対象にする。強制追加された場合もファイル名だけで拒否し、内容は検査ツールへ渡さない。
- `checks/secrets.mjs`: 一時リポジトリの合成データで、通常のコミットの成功と、秘密情報・補助ルール・禁止パス・push前の履歴検査による拒否を確認する。本体のコミット・pushは行わない。

誤検出は内容を確認してからルール単位で扱い、検出結果を一括で許可するベースラインは作らない。

## 検出の限界

氏名・住所を含む自由文や画像・音声内の個人情報は網羅できない。コミットの作成者名・メールアドレスはファイル内容の検査対象外なので、push前に別途確認する。予約された例示用メールとGitHubの非公開コミット用アドレスはメール補助ルールで許可する。フックはローカルの防止策であり、別の環境での未導入や意図的な回避まで強制的には防げない。

公式資料: [gitleaksの使い方・設定](https://github.com/gitleaks/gitleaks#readme)、[公式pre-commitの実行オプション](https://github.com/gitleaks/gitleaks/blob/master/.pre-commit-hooks.yaml)。

## 導入時の確認

2026-10-16にgitleaks 8.30.1を導入し、このリポジトリのフックを有効化した。一時リポジトリで通常のコミットと例示用メールの許可、秘密鍵形式の合成データ・メール・ローカルパス・電話・禁止パスのコミット拒否、ファイル削除後も履歴からの検出でpushを拒否することを確認した。既存40テスト・ビルド・Lint・フォーマット確認も成功。

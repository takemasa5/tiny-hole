# 全ステージの成長・テーマ行動・段階配置の改修案

作成・更新日: 2026-11-06 / 状態: 採用済みの改修案。本文は採用前の検討記録。

2026-11-06: オーナーが提案の進め方を採用。実装後の現在のルールと検証は [scale-growth-implementation.md](scale-growth-implementation.md) を参照。以下は採用前の検討記録。

## 提案の要約

推奨は「12段階程度の成長」「テーマに沿った行動と配置」「4つ程度のエリアを段階開放」「遠景の巨大物を簡略表示」「役目を終えた小物の撤去」を組み合わせる構成。巨大な世界を感じられる景色を残しながら、その時点で遊ぶ範囲に描画・行動・物理の処理を集中させる。

最初の試作は、会社で遮蔽物透過を確認し、港で小物からタンカーまでの成長・道路走行・停泊・段階配置を通す。その後、おもちゃの街でヒーロー対怪獣を検証してから全ステージへ展開する。以下の数値、追加物、ゲート、クリア目標、行動変更は採用前の案。

## 1. 目指す体験

全ステージで「消しゴムほどの物を集める穴」から始め、成長するたびに新しい大きさの物を飲み込めるようにする。終盤には、ビル・巨大ヒーロー・タンカー級の物を対象にする。

塊魂を参考にする点は、小さな物から巨大な物へ対象が変わり、最初に見上げていた物が後から小さく見える尺度の変化。既存の穴を操作する遊びに、この成長体験を取り入れる。

### 今回の依頼で示された方針

- 会社のような微小スタートと、大きな成長幅を他のステージにも適用する。
- 序盤は鉛筆・消しゴム程度、終盤は建物や巨大物を対象にする。
- 大きな物の背後に入っても、自分の穴を見失わず操作できるようにする。
- 車の道路走行、巨大ヒーローと怪獣の戦い、タンカーの停泊など、物にテーマと役割を持たせる。
- 個数と配置を見直し、成長による小物の撤去や、ゲート先の段階生成を検討する。

### 維持する既存仕様

- 穴は画面中央で、画面上の大きさを一定に保つ。実際の穴を拡大し、カメラを後退させる。
- 物理演算による傾き・落下、段階成長、ステージごとのテーマを維持する。
- 制限時間・失敗条件は設けない。通常UIはステージ・最終目標・メニューを中心とする。

以下の段階数・寸法・追加する物・最終目標・透過の数値は、採用確認と試遊調整が必要な提案。

穴の初期半径だけを変えると、他ステージには集められる小物がなく、進行できない。成長表・物の寸法と種類・配置・補充・目標を一緒に見直す必要がある。

現行の根拠は `src/game/stage.ts` の `LEVELS`・`OFFICE_LEVELS`・ステージ定義と、`docs/additional-stages.md`。描画・カメラは `src/game/runtime.ts` を確認した。

通常時の方向変更と、飲み込める大きさになってからの逃走は `walker.ts`。物体生成は `runtime.ts` の `createStage(...).map(createPhysicalObject)`。現在の全オブジェクトがランダム移動するわけではなく、静止・接触で動く物と歩行制御する物を分けて扱う必要がある。

## 3. 成長の流れ

推奨は12段階。まず港で、以下の仮の尺度が気持ちよくつながるか試す。寸法はゲーム内のメートル相当であり、実在の物の正確な寸法を示すものではない。

| レベル | 穴の直径の仮値 | 新しく狙う対象の例                     |
| ------ | -------------- | -------------------------------------- |
| 1      | 0.16           | 消しゴム、ナット、小石                 |
| 2      | 0.28           | 鉛筆、ボルト、小さな玩具               |
| 3      | 0.5            | 缶、ホチキス、小箱                     |
| 4      | 0.9            | ボール、バケツ、荷物                   |
| 5      | 1.6            | 椅子、小さな動物、人                   |
| 6      | 3              | 机、屋台、ドラム缶                     |
| 7      | 6              | 車、コンテナ、小舟                     |
| 8      | 12             | 家、倉庫、中型船                       |
| 9      | 24             | 大きな建物、港の設備                   |
| 10     | 48             | ビル、巨大クレーン                     |
| 11     | 96             | 巨大ヒーロー、大型建造物               |
| 12     | 180〜320       | ステージ固有の巨大目標。港ならタンカー |

レベル1〜3は手元の小物、4〜6は人の生活圏、7〜9は街・港の設備、10〜12は巨大な建造物や生物という4つのサイズ帯に分ける。寸法表は成長曲線の仮案で、表の各対象が必ずその直径で落ちるという保証ではない。特に人・椅子・細長い物は、姿勢を含めて対象レベルを調整する。

直径は全ステージ共通の確定値にはしない。特に長い船は高さだけで判断せず、幅・長さ・傾きと実際の落下を見て最終半径を決める。各対象が入る段階はモデルの寸法・姿勢で検証する。

- 基本は1段階で直径が約1.7〜2倍になる流れとし、最終段階は目標に合わせて調整する。
- 毎段階、直前には入らなかった代表的な物を複数配置する。大きさだけでなく、集める対象の見た目を変える。
- 同じ木や建物が、序盤は壁のように見え、中盤は狙う対象になり、終盤は小物として飲み込める配置を作る。
- 成長時は穴の実寸とカメラ距離を同じ比率で変える。補間演出を入れる場合も両者を同期し、表示径と落下位置を合わせる。
- 移動速度も尺度に合わせる。現行の半径に比例する移動を出発点に、序盤の精密操作と終盤の移動時間を試遊で調整する。

### 成長ポイントと配置

実体積をそのままポイントにすると尺度差が極端になるため、既存の種類別ポイント方式を拡張する。大きいサイズ帯の物ほど多く加点し、序盤の小物だけを延々と集める進め方になりにくくする。必要数は試遊で決め、現行の閾値2700や小物供給間隔をそのまま流用しない。

- 初期画面に入る物と、次の段階へ進める量を開始地点付近に確保する。序盤から広いマップを探し回らせない。
- 成長後に見える範囲にも、その段階に合った物を置く。大小の物の密度を、開始地点と成長後の探索範囲に合わせて調整する。
- 巨大物は同じ世界座標に簡略モデルとして見せ、成長してから取りに戻れるようにする。詳細なモデル・行動・剛体は必要な範囲で生成する。既存の道路・群落などに大小の物を混在させる。
- 地面にある物をまず集められる構成にする。机の上の小物を序盤の必須在庫にはしない。
- 在庫不足時の補充を全サイズ帯で成立させる。補充場所は遠方だけに偏らず、現在地から実際に回収可能な位置を確保する。
- 清掃車の大きさ・速度と、小物を押してしまう範囲も見直す。開始直後の必須在庫を失っても進行が止まらないことを確認する。
- 工場の回収時期は現行の「通常レベル8・小型レベル6」から見直し、必要な補充が終了する段階と整合させる。
- 各レベルで、到達可能な静止物だけでも次へ進める在庫を確保する。初案は必要ポイントの1.5倍を配置し、走る物をすべて追いかけなくても進めるようにする。1.5倍は検証用の余裕であり、進行保証は経路・実際の落下・補充も含めて確認する。
- 各サイズ帯で代表的な物を3〜5種類用意し、同じ小物を大量に集めるだけの区間を避ける。1レベルで主に集める個数は10〜20個程度から試し、実プレイで調整する。

## 5. 手前のオブジェクトの透過

「影に入る」は、光源が作る影ではなく、カメラから見て手前の物が穴を覆う状況として整理した。現在の描画コードではシャドウマップを有効化していないため、まず遮蔽物への対処を提案する。光源による暗い影も対象とする場合は、別に表示条件を確認する。

### 推奨する見え方

- 穴の中心または縁の周辺を隠す物を、自動で半透明にする。家具・木・人・建物・工場・最終目標を対象にする。
- 最初の試作は、そのオブジェクト全体を透過する。穴の周囲だけをくり抜く方式は、全体透過を試してから必要性を判断する。
- 不透明度は25〜35%を初案とする。輪郭と色を残し、穴と近くの小物が見える濃さへ調整する。
- 遮っている物が何個も重なる場合は、該当するすべてを透過する。重なりで穴が見えなくなる場合は、不透明度をさらに調整する。
- 穴が見える位置へ抜けたら元に戻す。透過・復帰は0.15〜0.25秒程度で切り替え、境界では短い猶予を設けてちらつきを防ぐ。
- 穴に落ちる最中も、縁や落下位置を隠している間は透過し、飲み込みの動きを追えるようにする。
- 透過は表示だけに適用する。当たり判定・落下・ポイント・歩行は維持する。

### 判定と描画の実装方針

カメラから穴の中心と縁の複数点へ線を引き、各点に達する前に遮る物を調べる。中央1本だけでは縁が隠れるケースを拾えないため、中心と周囲8点程度を初案とする。カメラより奥や、穴より先にある物は対象外にする。

判定はまず画面上の穴周辺と重なる物へ候補を絞り、実際の描画形状への判定を行う。カメラが大きな物の内部に入る場合や、近接面で切れる場合も確認し、通常の線の交差だけで拾えないケースを補う。

モデルは複数の部品でできているため、透過対象は物のIDでまとめ、部品間の濃さをそろえる。元のマテリアル状態を保持して正しく復帰させる。同じ種類の別個体まで透過しないよう、共有マテリアルの扱いを確認する。

透明物同士の描画順、奥行き書き込み、裏面、重なる家具や工場の煙突をブラウザで確認する。終了・ステージ切替・回収時には判定対象と追加した描画資源を解放する。透過した物に対する目標物タップの扱いも確認し、意図せず奥の目標を置き直さないようにする。

巨大な建物全体の透過が頻発して景色を失う場合は、穴周辺だけを透過する方式へ進む。全体透過は導入が小さい一方、重なる透明面が増える。穴周辺だけの透過は景色を保ちやすい一方、描画方式の検証が増えるため、最初の比較試遊で採用方式を決める。

## 6. テーマに沿った行動

### 基本方針

すべての物を動かす必要はない。「車は道を進み、作業員は仕事をし、船は停まっている」という違いを作る。ランダム性は仕事場の中の行き先や待ち時間などへ限定し、物の役割が見て分かる配置と動きにする。

| 対象                       | 通常時の行動案                                                   | 穴が近づいた場合・落下時                                                                                   |
| -------------------------- | ---------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| 車・配送トラック           | 道路の経路を走る。交差点では停止点と順番待ち。荷捌き場で短く停車 | 入るサイズになった場合も道路内で短く加速・停止する程度とし、建物内へ逃げない。支えを失ったら運転制御を解除 |
| 人・社員・作業員           | 歩道・廊下の決まった地点間を移動し、店・机・倉庫の前で仕事や休憩 | 入るサイズになったときだけ歩行可能な範囲で逃げる。安全になったら仕事へ戻る                                 |
| たぬき・ラクダ             | 餌場・木陰・水場を巡回し、ときどき立ち止まる                     | 入るサイズで近づかれたら逃げる。行き止まりで振動し続けないよう別の地点へ向かう                             |
| 巨大ヒーロー・怪獣         | 専用の広場で、接近→構え→攻撃→後退の短い対戦を繰り返す            | 入るサイズになって穴が近づいたら対戦を中断して回避。落下後は通常物理へ渡す                                 |
| タンカー・小舟             | 岸壁に決まった向きで停泊。小さな揺れや設備の動きで存在感を出す   | 逃走させず狙いやすい大物にする。回収可能時に固定を解除し、傾いて落ちる                                     |
| クレーン                   | 岸壁・搬送場所でフックやアームがゆっくり動く                     | 落下時に設備アニメーションを止め、本体と部品を一体で落とす                                                 |
| 汽車・兵隊                 | 線路を周回／広場を隊列で行進                                     | 線路上の汽車は経路を維持し、兵隊は入るサイズで隊列を崩して逃げる                                           |
| 鬼・亡者                   | 鬼は釜や門を巡回し、亡者は列を作って歩く                         | 入るサイズで逃げる。落下後は追跡・整列を解除                                                               |
| 建物・家具・コンテナ・小物 | 基本は静止。役割に合う場所にまとまって置く                       | 接触・支持の喪失によって動き、物理的に傾いて落ちる                                                         |

### ヒーローと怪獣の小さな場面

- 初案は1組2体。遠くから大きな姿と戦う動きを見せ、終盤の目標を予告する。
- 攻撃はポーズ・向き・短い移動による演出を中心とし、HP・勝敗・建物破壊・プレイヤーへのダメージは初案に含めない。戦闘だけで回収対象が消える状況を作らない。
- 片方を回収したら、残った側は探す仕草から広場の巡回へ移る。消えた相手を追い続けない。
- 一体につき単純な剛体で始め、腕や脚ごとの物理関節は導入しない。落下時はポーズを固定し、本体を剛体として落とす。
- 見せ場の最中も収集を強制的に待たせず、必要な大きさなら割り込んで飲み込めるようにする。

### 行動と物理の優先順位

「落下中 → 飲み込めるサイズでの回避 → 通常の仕事・走行・戦闘」の順に優先する。停泊船・建物などは回避を持たない。行動制御が落下中の物を直立に戻したり、元の経路へ引き戻したりしない。

道路・歩道・線路・戦闘広場は、初案では手で設計した経路と停止点を使う。汎用の街づくりや経路探索システムは前提にしない。経路が物や穴で塞がれた場合は短く待ち、再開できなければ予約した折り返し地点へ戻す。進行に必須の在庫を移動物だけに依存させない。

停泊船の揺れは表示演出から試す。現行の港には水上移動・浮力がないため、初案は水面風の地面を通常の床として通行可能にし、その面の穴へ船も落ちるルールを提案する。浮力や航海を望む場合は別の仕様として扱う。固定物や演出から物理へ切り替えるときは、その瞬間の位置・向きに合わせて衝突形状を用意し、支持を失う前に切り替える。

## 7. エリア・配置・生成の管理

### 比較と推奨

| 方式                           | 利点                                             | 課題                                               | 扱い                                     |
| ------------------------------ | ------------------------------------------------ | -------------------------------------------------- | ---------------------------------------- |
| 全配置・全剛体を最初から生成   | 世界の連続性を作りやすい                         | 初期生成、物理、メモリが物量全体に依存する         | 初案では採用しない                       |
| ゲートだけで次を生成           | 生成範囲を明確に限定できる                       | 境界での処理集中、突然の出現、行き止まり感         | エリア開放に使用し、予告・先行準備で補う |
| 距離だけで生成・停止           | 自由な探索に向く                                 | 巨大な視界と成長在庫の保証、往復の状態管理が難しい | 開放済みエリア内の稼働管理に使用         |
| サイズ帯・ゲート・距離の組合せ | 成長の区切り、世界の予告、同時物量を両立しやすい | 生成・撤去・回収の状態を分ける必要がある           | 推奨                                     |

現行は2026-10-30に地区別の配置を廃止している。今回のゲート付きエリアは、その確定仕様を変更する提案であり、自動採用しない。細かい物の種類ごとに地区を分離するのでなく、大きさに応じて行ける範囲が広がり、各エリア内には複数のサイズを混在させる案。

### 港の4エリア案

| エリア          | 初めて入れる段階の仮値 | 配置と場面                                                   | 次への接続                       |
| --------------- | ---------------------- | ------------------------------------------------------------ | -------------------------------- |
| A: 作業場の足元 | レベル1                | 落ちた小物・釣り具・缶。近くに箱や作業員を見せる             | レベル4で作業場の出口を開放      |
| B: 荷捌き場     | レベル4                | 樽・木箱・作業員・台車。道路上を配送車が巡回                 | レベル7で搬送路のゲートを開放    |
| C: 倉庫・埠頭   | レベル7                | 車・コンテナ・倉庫・小舟・クレーン                           | レベル10で大型岸壁への接続を開放 |
| D: 大型岸壁     | レベル10               | 大型設備・大きな倉庫・タンカー。最終成長に十分な中間物も配置 | レベル12で最終目標を狙う         |

- 序盤からタンカーの船体の一部、クレーン、倉庫の輪郭を適切な場所に見せる。カメラが引くほど、それらの全体と位置関係が分かる構図にする。
- レベル1からタンカーまで同じ世界座標上の連続した場所に置く。ゲート通過で別の縮尺の世界へ突然切り替えない。
- ゲートは必要段階の表示と見た目・移動制限を一致させる。成長後は自動で開き、後戻りもできる。足止めはサイズの理解に使い、鍵探しや追加ミッションを要求しない。
- ゲートは通常の収集物と分けた境界として扱い、開放前に飲み込んで抜けられないようにする。開放後は移動・穴の拡大・カメラの邪魔をしない位置へ退かす。
- 穴の中心だけで通行判定せず、穴半径も含めて未開放側への侵入を防ぐ。レベルが一度に複数上がった場合にも、必要な全エリアの開放と在庫を準備する。
- 机の上から床への落差や階段は初期試作に含めず、足元の平面で始める。会社の外への接続も、段差や天井との干渉がない経路を別途設計する。

### オブジェクトの状態

物の存在と、描画・行動・物理の稼働を分ける。初期状態で全種類の詳細モデルと剛体を作る必要はない。

| 状態                     | 保持・処理するもの                                             | 切り替える条件                   |
| ------------------------ | -------------------------------------------------------------- | -------------------------------- |
| 未生成                   | ID・種類・配置先・シードなどの軽い定義だけ                     | エリアの準備段階に入る           |
| 遠景・予告               | 選んだ建物や巨大物の簡略モデル。詳細剛体や細かい行動は作らない | 接近・エリア開放・収集対象化     |
| 近傍で稼働               | 遊びに必要な描画・衝突形状・行動。静止物は睡眠も使う           | 穴や移動物と接触し得る範囲に入る |
| 遠方で休止               | ID・位置・向き・行動の進み具合を保持し、不要な処理を止める     | 稼働範囲を十分離れる             |
| 役目を終え撤去           | 二度と生成しない記録を保持し、描画・剛体・関連登録を解放       | 小さすぎる物の撤去条件を満たす   |
| 回収済み／場外へ撤去済み | 二重生成・二重加点を防ぐ記録だけ                               | 既存の回収・場外判定             |

稼働範囲は物体の中心距離だけでは判定しない。大きな建物・長い船の外形、次の更新までの走行距離、穴の移動・成長幅を含めた余白を持たせる。まだ回収できない大物も、接触範囲に入るなら支持・衝突を用意する。積み重なりや相互接触中の物はまとまりで稼働させ、画面外だからという理由だけで物理を止めない。開始・停止に異なる距離を使い、境界での作成・破棄の往復を抑える。

休止は未生成へ戻すことではない。再訪時に物が初期位置へ戻ったり回収済みの物が復活したりしないよう、初期物・補充物に共通の安定したIDと状態を持たせる。遠方の車などは休止・再開から始め、離れている間も街全体を精密にシミュレーションする設計にはしない。近傍への復帰時は重なりを検査する。

### 先行準備とゲート開放

1. 現在のエリアは、成長に使う物を優先して作る。将来の小物は定義だけ保持する。
2. 次のエリアは、開放の1段階前を目安にモデルと生成データを少量ずつ準備する。遠景の巨大物はこの時期より前から見せてよい。
3. 必要レベルへの到達時には、入口周辺の床・支持・在庫・移動経路の準備を確認してから開放する。未生成の空白へ進ませない。
4. 残りは入口から見えない場所などで分割生成する。画面内への突然の出現や、プレイヤー・既存物と重なる生成を避ける。
5. 旧エリアの小物を撤去し、空いた予算を新エリアへ回す。入口準備中は旧エリアで収集を続けられるようにする。生成失敗は表示・再試行できる状態にし、在庫を一緒に失わせない。

先行準備で、次のエリアの全剛体まで作る必要はない。まず軽い定義と表示資源、入口で必要な物を準備する。「レベル到達まで先の処理をすべてゼロにする」案より多少の先行処理を使う代わりに、成長時の停止を減らす狙い。

### 小さすぎる物の撤去

- 初案は「主な対象より2サイズ帯以上前」「画面上で2〜3ピクセル未満」「画面外または十分離れた場所」をすべて満たした通常物から撤去する。単にレベルが1上がっただけで一斉に消さない。
- 落下中、穴の縁付近、透過対象、現在の成長に必要な在庫、目標、別の物を支える物は撤去しない。接触中の積み上げも保護する。
- 撤去は収集と別の理由で記録し、ポイントを付与しない。回収数やクリア条件にも加えない。
- 撤去した種類を古い補充処理が再生成しないよう、供給候補も現在のサイズ帯に合わせる。必要ポイントを再計算し、在庫不足なら次の段階へ進める物を回収可能な位置へ補充する。
- 比較の目印となる建物・木などは、小さくなっても一部を景色として残す。世界をすべて消すことによって負荷を下げる案にはしない。

## 8. 個数と補充の見直し

### 初期の個数より、同時に処理する数を決める

現在の初期物量は、広場560、山460、アメリカ452、エジプト270、港288、おもちゃ360、会社274、地獄196（工場は別枠）。積み上げの各段も個別の物として数える。これを12レベル分へそのまま増やすと、成長の面白さより物量が先に増える。

以下は港の試作で使う仮の上限。性能の実測に基づく安全値ではなく、測定しながら変える出発点とする。

| 指標                                 | 仮の目安   | 使い方                                                           |
| ------------------------------------ | ---------- | ---------------------------------------------------------------- |
| 同時に存在する通常の物理オブジェクト | 150〜250個 | 稼働中の固定・睡眠・移動・落下を含めて数える。床・境界は別途測る |
| 毎ステップ行動を更新する物           | 20〜40体   | 車・人・動物など。全在庫を常時歩かせない                         |
| 大きな見せ場を作る物                 | 2〜6体     | ヒーローと怪獣など。上記の物量の内数                             |
| 現在のレベルで主に狙う物             | 30〜60個   | 静止物を中心に複数の取り方を用意。上記の物量の内数               |

遠景の数は物理上限と別に数え、描画回数・頂点数・透明面の重なり・メモリで調整する。単純な小箱250個と、多部品のキャラクター250体は同じ負荷と扱わない。上限を越える場合も、進行に必要な物を無条件に削らず、遠方の休止や旧サイズ帯の撤去を先に行う。

### 補充もテーマに合わせる

全種類を工場の煙突から無差別に排出する方式は見直す。小物は作業場の箱や補充口、荷物は倉庫、車は道路の入口など、役割に合う供給元と候補を設定する。画面内の空中に突然出すことを避け、入ってきたことが分かる短い演出を使う。

補充は物量を増やすことより、進行在庫の回復を優先する。未開放のゲート先に十分な物があっても、現在の在庫として数えない。必要な静止物を確保し、移動物・場外撤去・清掃車・小物の撤去だけで成長不能にならないようにする。

供給元は、必要な補充を終えたら停止し、そのサイズで入る場合に回収可能とする。すべてを現行のレベル8・6で停止する設計は引き継がない。清掃車も道路・作業区画の役割へ絞り、開始地点の小物やゲート手前の必須在庫を無制限に持ち去らせない。この変更も採用確認の対象。

## 9. 技術面で先に検証すること

今回の尺度差は会社の20倍を大きく上回る。既存の数値の置き換えだけで成立するとは扱わない。

| 検証点       | 主な確認内容                                                                           |
| ------------ | -------------------------------------------------------------------------------------- |
| 微小物の物理 | 接触の許容値、床のすり抜け、睡眠、穴の縁での支持。会社の既存寸法を出発点にする         |
| 巨大物の物理 | 小物との質量差、長い船の傾き、床での安定、回収判定までの落下時間                       |
| マップと床   | 最終半径で移動余地が残る境界、床の広さ、巨大な穴の円周近似、広い座標での精度           |
| カメラ       | 微小物と巨大物の両方で近接・遠方の表示が欠けないこと。現行のnear 0.08・far 800の適否   |
| 穴の内部表現 | 現行の固定深さ30・底面位置などが、巨大な穴の落下表現にも合うか                         |
| 透過         | 穴の縁まで見えるか、複数の遮蔽物・内部に入ったカメラ・移動中のちらつき                 |
| 端末負荷     | 序盤・成長直後・複数物の落下・大量透過・終盤の描画時間と物理時間                       |
| 段階生成     | ゲート開放前の準備、生成の分割、衝突の先行有効化、往復時の状態復元、生成失敗からの回復 |
| 行動切替     | 経路の渋滞、戦闘相手の回収、停泊から落下への切替、休止からの復帰時の重なり             |
| 資源の寿命   | 小物撤去・回収・ステージ切替で、メッシュ・剛体・行動・透過登録・供給枠が残らないこと   |

最初は既存のThree.js・Rapier構成で検証し、追加ライブラリは前提にしない。段階生成と物理の稼働管理を初期設計へ含め、その距離・個数・準備量は測定で決める。同形状の描画共有や細かいモデルの簡略化は、描画が負荷の原因と分かった範囲から採用する。世界全体を成長のたびに縮小する方式への変更は、初案には含めない。

主な変更対象は、`stage.ts` の成長表・物とステージ定義・配置、`runtime.ts` のカメラと接続処理、`walker.ts` と追加するテーマ行動、`object-supply.ts`・`supply-factory.ts` の補充と回収条件、各モデル描画。透過・エリア開放・物の稼働管理は責務を分ける。床・回収・清掃車は検証で必要な範囲を修正し、汎用エンジン化は行わない。

カメラのnear/far、物理の許容値、床の広さ、穴内部の深さ、回収面までの距離は、同時に扱うサイズ帯に合わせて検証する。巨大物の上端が固定の回収面を通るまで長時間待つ問題にも注意する。座標精度が不足した場合の原点移動などは、まず測定で必要性を確かめてから別途設計する。

測定はフレーム時間の中央値・95パーセンタイル、物理・床更新・行動・透過判定の時間、描画回数、剛体数、メモリ、生成時の最大停止時間を記録する。PCで60fps、対象iPhoneで30fpsを暫定目標とし、成長直後・ゲート開放・密集した落下・多重透過・終盤で比較する。対象iPhoneの機種とOSは実装検証前に決める。物理の時間刻みを粗くすることを最初の負荷対策にせず、同時に稼働させる範囲と描画から調整する。

生成を遅らせることと、配布データをネットワークから後で取得することは別。既存のオフライン起動を維持するため、必要なモデル定義・音・コードは端末へ保存し、プレイ中は保存済みデータから生成する。

## 10. 遊んで確認する順序

1. **会社で透過を試す。** 既存の微小スタートを使い、机・棚・社員・工場の後ろでも穴を追えるか確認する。成長の再設計とは分けて評価する。
2. **港を小物からタンカーまで通す。** まず簡易形状で12段階・4エリア・段階生成・小物撤去・補充・巨大目標・カメラ・物理を接続する。配送車の道路走行とタンカーの停泊を加え、成長ごとの対象の変化と負荷を確認してからモデルを作り込む。
3. **おもちゃの街で戦闘を試す。** ヒーローと怪獣の1組を置き、遠景からの予告・戦闘中の回収・相手不在・落下切替を確認する。港で作った成長と稼働管理を再利用できるか評価する。
4. **残りのステージへ展開する。** 広場・山・アメリカ・エジプト・地獄と、会社の終盤拡張を順次適用する。ステージごとの目標・テーマ行動・成長のつながりを試遊する。
5. **全8ステージを通して調整する。** 成長速度、供給、清掃車、タッチ操作、クリア、自動移行、再開、オフライン保存を確認する。

各段階で自動テストとPCブラウザ確認を行い、微小スタートと大量透過は早期にiPhone実機でも評価する。PC・WebKit・iPhone実機の結果は分けて記録する。

### 採用後の完了条件

- 全ステージが小物から始まり、各段階で新しく飲み込める代表的な物がある。
- 複数の配置シードで、開始地点から成長・巨大目標の回収まで通常操作で進める。
- 在庫不足・清掃車による場外撤去・工場回収が原因で成長不能にならない。
- 未開放先の在庫を当てにしなくてもゲートを開けられ、複数段階の成長・再訪・供給後も回収済みや撤去済みの物が復活しない。
- 車は道路、汽車は線路に沿い、人は役割のある地点へ向かう。戦闘相手を回収しても残った側が破綻しない。
- ゲート開放時の空白・重なり生成・目立つ出現を避け、稼働数と撤去後の資源解放を測定できる。
- 穴が手前の物に隠れた場合も、中心と縁が識別でき、遮蔽物を抜けると表示が戻る。
- 微小物・長い物・巨大物が物理的に落下し、成長・加点・クリアが一度ずつ処理される。
- 穴の画面上の大きさと操作感が成長前後で保たれる。
- 適切なテスト・ビルド・Lint・フォーマット確認と、対象端末での操作・負荷の確認結果を残す。
- 採用内容に合わせてゲーム仕様・技術設計・ステージ資料を更新する。

## 11. 実装前に決める事項

推奨する採用単位は、まず「会社での透過」と「港での微小スタートからタンカーまでの試作」。港には道路走行・停泊・4エリアの段階開放・小物撤去も含める。その次に、おもちゃの街のヒーロー対怪獣を追加する。他ステージのモデルを大量に作る前に、尺度差・行動・操作性・負荷を確認する。

実装の採用確認で扱う主な点は次のとおり。細かい不透明度・個数・待ち時間などは、採用した試作の仮値として評価し、すべてを事前確定させる必要はない。

1. **成長段階:** 12段階を初案として試すか。8段階を維持する場合は1回の成長幅が大きくなり、中間の物を狙う機会が減る。
2. **最終目標:** 上記の候補を採用するか。特に港の「クレーン→タンカー」、会社の「社長→本社ビル」はクリア条件の変更を伴う。
3. **透過の見せ方:** まず遮る物全体を半透明にするか。穴の周りだけを透過する場合は、追加の描画方式の検証が必要になる。
4. **エリアの構成:** 4サイズ帯・レベル4/7/10でのゲート開放を試すか。開放済み範囲は自由に往復できる案。
5. **テーマ行動と補充:** 無目的な歩行・全種類の工場排出・清掃車の役割を、場所に合う動きと供給へ変更するか。
6. **港のルール:** 水面も通常の床として穴が進め、停泊船を回収する簡略案で試すか。浮力・航行は別途とする。

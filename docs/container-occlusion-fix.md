# レベル1で箱全体が透過してしまう問題

2026-11-07 / ローカル修正。オーナーが直前の修正版をiPhoneで確認し、「レベル1では激しく点滅するが、レベル2になると治る」と報告した。前の[移動時の表示補間](box-motion-stability.md)とは別に調査した。

同日その後、オーナーがこの修正後も点滅を確認した。iPhoneの症状は未解消。[実機で描画条件を比較する診断画面](iphone-render-diagnostic.md)を追加。以下の不要な透過の修正を、iPhoneの点滅原因の確定・解消とは扱わない。

## 確認した条件

箱の壁・縁・蓋は1つのグループで物理演算と回収を扱う。従来の透過処理はこのグループ全体を1つの対象としていたため、手前の壁が穴全体を隠すと、穴を隠していない奥の壁・横の壁・大きな蓋まで一括で半透明になっていた。移動中にこの判定へ出入りすると、関係のない広い領域も濃さが切り替わる。

実際の箱と透過クラスを使い、390×844・DPR2のカメラで条件を比較した。レベル1（半径0.08、穴の位置z=0.4）は手前の壁に穴全体が隠れる。従来は奥壁と蓋も透過した。レベル2（半径0.14、z=0.39）はカメラが後退し、同じ箱の壁が穴全体を隠す条件に入らず、透過しなかった。

このレベル差はオーナーの観測と整合する。ただし、iPhone上の激しい点滅を直接録画・計測して原因を確定したものではない。PCの描画用シーンで確認できたのは、箱全体の不要な透過と、その切り替わりがレベル1でだけ発生する条件である。

## 修正

箱・部屋・家などの囲いは、「穴へ入らない大きさ」「穴の中心と周囲8点のすべてが実際に遮られる」という条件をグループ単位で維持する。その条件を満たした場合に、カメラと穴の間で実際に交差した面だけを透過する。奥の壁や蓋など、穴を隠していない面は元の材質のままにする。

2枚の壁が組み合わさって穴全体を隠す場合は、両方の面を対象にする。1枚ずつでは穴全体を覆わないという理由で透過が止まることを防ぐ。穴の一部しか遮らない場合や、囲い全体が穴へ入るサイズになった場合は透過しない。後者では配下の面の材質もすべて復帰・解放する。

家具などの通常オブジェクトは従来どおり全体を透過する。透過の25%の濃さ、MSAA対応時の描画方式、0.12秒の短い判定欠落の猶予、材質の再利用を維持する。穴・カメラの表示補間、物理演算、成長、出口、種類・寸法・配置も変更しない。

## 検証

- 自動テスト316件・24ファイル、型チェックを含むビルド、Lint、変更ファイルのPrettierが成功。
- 新しい5テストで、レベル1の手前の壁だけの透過、レベル2での透過なし、2枚の面による遮蔽とまとめた復帰、一部遮蔽の除外、移動による透過切り替わり中も奥壁・蓋が変化しないことを確認した。修正前は奥壁の材質も変わるため回帰テストが失敗する記録を保存した。
- PC Chromiumの描画比較では、修正前のレベル1は手前・奥壁・蓋のすべてが透過し、修正後は手前の壁と縁だけが透過した。レベル2の表示は修正前後で透過なし。実行時エラーは0。これは実際のクラスを組み合わせた描画専用シーンで、通常のゲーム配置・操作の確認とは区別する。
